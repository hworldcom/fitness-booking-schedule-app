## Current background delivery

[DEV0392](../../tickets/archive/frontend/DEV0392-optimize-public-background-image-delivery.md) step 1 imports the three original JPEGs as static image data. Next.js includes each file's content hash in its generated static media URL (`/_next/static/media/` locally, `/_next/static/immutable/media/` in the verified UAT build), and the optimizer uses that versioned source for its responsive URLs. Unchanged images can remain fresh in the browser's immutable cache; changing image bytes and rebuilding generates a new URL. Browser eviction, force reload and a changed optimizer variant can still require a request. UAT serves these optimized images with `Cache-Control: public,max-age=31536000,immutable` (one year); the local production optimizer returned `public, max-age=315360000, immutable` (ten years). Actual browser reuse and replacement checks are recorded in the ticket; neither duration guarantees the browser will retain a cached file.

Step 1 retained quality 95 to verify caching independently. Step 2 selects quality 85 after comparing actual optimized responses at 95, 85 and 75 in matching desktop, phone and high-density crops. The bounded optimizer allowlist is now 75/85/95, preserving other images' default quality and compatibility with older quality-95 requests. Step 3 uses `sizes="100vw"` for Home/Explore and keeps `(max-width: 480px) 480px, 100vw` explicitly for Events. Its double-height phone frame needs 480 CSS pixels of source width even when the visible viewport is narrower. Intermediate 960, 1440 and 2880 device widths reduce rounding up for phone and desktop pixel densities; all previous width variants remain available. Original JPEGs, format settings, eager/high-priority loading, banner dimensions and CSS crops are unchanged. Public background compression/caching does not change uploaded/profile-image normalization, authorization or caching, and no broad cache override is added.
